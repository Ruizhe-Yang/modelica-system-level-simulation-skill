1. 这个 Skill 的定位

它不是“帮 Codex 写 Modelica 代码的一段提示词”，而是一套系统级 Modelica 工程工作规程。核心目标是让 Codex 既会建模，也会判断模型是否值得这样建、是否画得清楚、是否运行正确、为什么运行慢、优化后是否仍保持工程有效性，以及最终如何形成可交接的完整说明。

架构

先结构、后方程

从真实系统边界、功能/过程归属和共享耦合网络推导分层，不固定套用机电热信等领域模板。

图形

可视模型即工程接口

Icon/Diagram 是模型架构的一部分，而非最后装饰；强调语义图标、端口几何、可读连线和层次导航。

验证

仿真完成 ≠ 模型正确

每次重要运行后都读取状态/KPI并做数值、物理、功能和性能 sanity check。

诊断

按阶段定位问题

把失败拆成 check、flatten、build、initialize/simulate、trajectory、profiling、variable trace。

性能

性能是架构指标

优先消除冗余状态、无价值细节、事件爆炸与偶然代数复杂度，再谈求解器参数。

交付

一个累计说明文件

模型/结果之外，默认只保留一个 MODEL_ENGINEERING_REPORT.md，集中承载全过程和评价。

4. 图标绘制与 Diagram 布局的增强

v3 吸收了公开 annotate-modelica-graphics 的有价值思路，但不依赖 Wolfram 的专用脚本，而是形成适合你的项目级图形规范。

4.1 先识别模型角色

package、connector、物理源/边界、设备、控制器、传感器/observer、adapter、subsystem、experiment、behavior core 分别采用不同视觉策略。

4.2 语义图标而非统一方框

读取类名、描述、端口和必要的内部语义，提炼 1–3 个工程特征，用 Modelica 原生矢量图元表达；只有 F0 架构占位阶段才允许 generic box。

4.3 非破坏式修改

默认保留已人工调好的 Placement、Line、Icon、Diagram；除非明确要求，否则不能为了自动重排而清空重画。

4.4 连接图驱动布局

先识别主路径、分支、反馈强连通组、共享总线/网络和外部边界，再安排组件位置与正交线路，而不是逐个“就近放置”。

Visual QA

最终检查语义可识别性、家族一致性、端口边规则、文字可读性、越界图形、线交叉、绕线、反馈路径、通道走廊以及缩小视图下的可读性。新增 scripts/audit_modelica_visuals.py 提供静态启发式检查，但真正的最终门仍是 OMEdit/MCP 或截图中的视觉检查。

这条链解决了一个常见问题：以前 Codex 看到“仿真失败”后很容易直接改 solver、容差或初值；现在必须先确认失败发生在哪个阶段，并把问题分类为路径/依赖、结构不平衡、初始化、非线性收敛、事件爆炸、刚性、重复状态、结果输出、外部接口等，再选择最小侵入的修复方式。

性能优化约束：求解器调参被放到优化序列后部。优先处理无价值保真度、重复状态、事件密集开关、偶然代数耦合、过量结果输出；每次优化必须在同一 canonical case 上比较速度与 KPI 偏差。

新增 scripts/diagnose_openmodelica.py，可通过 OMC 执行 check / flatten / build / simulate / profile 的轻量 staged runner，并支持超时限制，避免明显失控的模型长时间占用仿真。

6. 你新增的“唯一完整说明文件”规则

这是 v3 最重要的工程交付约束之一。每轮 Codex 完成模型优化后，除模型/配置源文件和需要保留的结果文件外，默认只输出或更新一个：

MODEL_ENGINEERING_REPORT.md

不再分别留下 architecture_report.md、icon_report.md、diagnosis_report.md、optimization_notes.md、test_summary.md 等碎片化文档。OpenModelica profiler HTML、日志、MOS、JSON/XML 等仍可在工作过程中生成，但默认作为中间证据；关键结论写进唯一的 Markdown 报告。

报告不是“这次改了什么”的薄日志，而是最终项目说明书

8. 安装与使用

用户级安装

%USERPROFILE%\.agents\skills\modelica-system-level-simulation\

项目级安装

<ProjectRoot>\.agents\skills\modelica-system-level-simulation\

将本次输出 ZIP 解压，使 SKILL.md 直接位于上述 skill 目录下。

典型调用

$modelica-system-level-simulation
全面检查当前 Modelica 工程，先建立基线并分阶段诊断，再优化架构、图标、Diagram、参数配置和仿真性能。
保持现有有效接口；每次修改后完成验证和结果读取。
最终除模型与仿真结果外，只保留并更新 MODEL_ENGINEERING_REPORT.md。

专项调用示例

# 图形专项
$modelica-system-level-simulation
只增强整个库的 Icon/Diagram。不得修改模型物理方程；保留人工调好的 annotation，
对 generic placeholder 做语义化重绘，并做 Visual QA。

# 性能专项
$modelica-system-level-simulation
诊断当前总体模型为什么运行慢。按 check→flatten→build→simulate→profile 分阶段定位，
在保持关键 KPI 的前提下优先做结构/保真度优化，不要先放宽 tolerance。

# 参数化专项
$modelica-system-level-simulation
把工程参数整理成外部 Excel/CSV → 校验 → 生成 Modelica record 的配置链，
仿真时不得实时解析 Excel。

9. 吸收的开源能力及改造方式

  • WolframResearch/system-modeler-ai-toolkit：重点参考 modelica-model-architecture、annotate-modelica-graphics、diagnose-modelica、simulate-modelica 的工作流思想。
    https://github.com/WolframResearch/system-modeler-ai-toolkit
  • LunCoSim：参考 run-modelica 与 inspect-simulation 的“Agent 自己运行并读取结果”的闭环理念，同时去掉 USD/Rust/LunCoSim 专属假设。
    https://github.com/LunCoSim/lunco-sim
  • OpenModelica：使用官方 scripting API 的 checkModel、instantiateModel、buildModel、simulate、getErrorString，并利用性能 profiling；OMEdit 新版 MCP 作为可选执行入口。
    https://openmodelica.org/
  • OpenAI Agent Skills 规范：采用 SKILL.md + agents/openai.yaml + references + scripts + assets/templates 的渐进式 Skill 结构。
不是简单拼接：本 Skill 没有把 Wolfram 的 WSMKernelX 执行层搬进来，也没有复制 LunCoSim 的 USD/Rust 体系；真正保留下来的是架构、图形、诊断和观察闭环的通用思想，并重新落到 OpenModelica 和你的系统级建模方法上。

10. 对这套专属 Skill 的评价

维度评价说明
系统级建模适配很强不是组件代码生成器，而是从系统边界、功能归属、耦合网络到实验入口的全链条规程。
OpenModelica 适配强执行诊断逻辑已经按 OMC scripting 和 profiling 重写，且不强依赖 OMEdit MCP。
图形工程能力明显增强比 v2 多了 semantic glyph、non-destructive workflow、graph-driven layout 和独立视觉审计。
诊断/性能能力明显增强从“性能原则”升级到可执行的 staged diagnosis + profile + KPI regression。
工程交付性非常强单一累计 Markdown 报告避免项目越做越多、说明文件越散，特别适合 Codex 多轮迭代。
自动化程度中高已有静态审计和 OMC staged runner；复杂语义图标仍需要 Agent 结合模型含义判断，这是合理的人机/Agent分工。
潜在限制需持续迭代Modelica 完整语法难以靠正则审计；visual audit 是启发式；不同第三方库/OMC版本的诊断输出仍需按项目适配。

总体而言，v3 已经从“Modelica 总体建模规范”升级为Modelica 系统级工程 Agent 工作流。它最有价值的不是某一个规则，而是把“建模—可视化—诊断—运行—观察—优化—验证—交付”变成了 Codex 必须遵守的闭环。
