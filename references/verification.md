# 诊断与验证：从实际证据闭环

## 分层诊断

D0盘点/依赖/类/配置 → D1加载/查找/基础平衡 → D2展开/继承/重声明 → D3翻译/编译 → D4初始化和积分 → D5结果可读/物理/KPI/事件 → D6必要性能定位 → D7按疑点回溯来源。

每层读实际错误和输出。名称/库缺失先修路径或版本；方程不平衡先查连接、参考和状态重复；初态冲突查独立fixed及代数约束；运行收敛查活动工况、事件、尺度和有效域；结果缺失查保存、格式、路径、过滤与别名。一个成功checkModel不代表完整任务已跑。

OpenModelica可用时参考checkModel、instantiateModel、buildModel、simulate及getErrorString，实际参数按安装文档确认。脚本应分开各层日志和墙钟，避免把导出/后处理时间混成积分。MWorks、其他引擎各自给出状态，不能继承另一个引擎PASS。

## 结果的最低核对

读取原始文件，确认终点、关键列、单位/方向、有限性和预计会变化的量。检查异常常值、意外饱和、漂移、尖峰、重复模式、库存小于零、事件抖振。真正恒定的参考不要求非平凡变化。没有保存某输出是合同/保存问题，不能通过造数补列。

空窗口/空集合、NaN、提前中止和缺数据不PASS。按时间积分/时间加权平均，事件重复时刻不重复计时；离散码按事件或保持值比较，不线性插值。保存间隔不是solver步长，也不是传感采样周期。亚秒峰值需足够局部输出/求解点，不能拿1秒网格证明更细事件精度。

## 独立账本与回归

明确定义质量、电能/电荷、热能、机械功、数据的系统边界。内部交换不重复计数，未建环境出口和开放系统动量/能量流按原简化定义。复算使用原始力、流、功、库存，不读取人为构造恒零残差替代。

纯重命名/Documentation/图形先保护行为与配置；结构等效迁移比关键连续轨迹、离散顺序、初态及边界；实际行为修复允许明确窗口/量义改变，其余范围回归。差分阈值在运行前冻结，不由结果倒推。源码token相同支持“未改非文档实现”，不是全工具渲染/数值执行一致证明。

## 结论分开

MainConformance（R）、RecommendationAdoption（S）、ReferenceSelection（F）、StaticCheck、Execution、ProjectAcceptance、PlatformStatus、ExternalValidity各自记录。用户认可的参考模型与每次软件实际测得的结论分清。已有PARTIAL/UNKNOWN保持其来源。

## 只有辅助任务时

检查类定义/说明覆盖、注释语法位置、完整source-span差异、数据/图片字节、生成元数据与新旧身份。可以读取init XML的description；没有新编译结果只能提供源声明覆盖证据。不得为描述显示打开HideResult、添加输出、恢复缺失显示模型或改变结果filter。

## 外部资料

安装库源码优先于对类名/端口的记忆。外部资料主要约束物理边界/参数来源，未经提供的数值不要填零或制造标定。证据分类为用户来源、源码检查、原运行、当前运行、外部资料、工程假设。不能把绘图示例升为行为实现。

## v0.8 具体静态工具范围

`audit_roles.py` 只按提供映射进行有限源级审查，静态连接模板、未展开库继承和重声明可输出 REVIEW_REQUIRED。`connection_colors.py` 核对实际端点，不将 Icon 内 Line 当作连接线；支持族以工具注册表为准。`verify_aux_only.py --allow-connection-colors` 只豁免 connect 的 Line.color；points、thickness、Icon/Diagram原语、experiment、Evaluate 和普通字符串仍受保护。所有非 `.mo` 变化都应配精确白名单并单独审查。
