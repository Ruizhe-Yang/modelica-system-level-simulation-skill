# 模型角色与白箱/黑箱详细合同

本节是 M05、M07、M08 的展开，而不是另外一套抽象口号。**TB、SB、AB 都是白箱模型：打开它，应看到“有哪些组成、参数如何分配、接口如何连接”，而不是在装配层寻找控制律或物理方程。BU、LU 对上层提供黑箱边界：上层按公开接口使用，行为由单元本身负责。** 黑箱不等于闭源、加密或黑色图标。

M05/M07/M08 对角色和有效实现的真实性要求为 **必须**。下文标注“建议”的分层习惯、文件安排、展示方式不升级为强制。角色在映射表中记录即可，既不要求文件名前缀，也不要求使用厂商私有注解。

## 1. 角色一览：里面应该有什么

| 概念角色 | 必须表达的责任 | 应有内容 | 不应放入的内容 | 可直接使用的功能子实例 |
|---|---|---|---|---|
| **TB 顶层盒** | 一个明确用途的完整实验入口；闭合外部输入和必要上下文 | 生效配置、系统/环境等实例、公开结果边界、连接、实验设置 | 本层物理状态、控制算法、运行表达式绑定、用初始方程补装配 | SB、AB、BU、LU；不把 TB 作为另一个系统的功能子实例 |
| **SB 系统盒** | 一个实际系统、分系统或有实际价值的集成边界 | 公开接口、配置分配、子系统/设备实例、逐层连接、Diagram | 跨系统本构计算、隐藏控制/测量、重复库存、内部路径穿透 | SB、AB、BU、LU；不包含实验入口 TB |
| **AB 装配盒** | 多个黑箱共同形成的末级局部装配 | 对外接口、静态配置、两个及以上有作用的 BU/LU、连接 | 嵌套系统/装配却仍称末级 AB；本层行为；无意义凑数实例 | BU、LU；库单元内部层次不按项目 AB 再拆 |
| **BU 项目行为单元** | 内聚的本构、算法、采集、执行或接口转换 | 参数、公开端口、内部变量、方程/算法、必要状态与初始化 | connect、独立运行 model/block 子实例、另一套物理库存、对外隐藏的数据通道 | 不包含独立运行子实例；允许函数调用、record、type、connector |
| **LU 标准库复用单元** | 按原合同使用 MSL 组件 | 原始 MSL 类和参数；可有不改行为的本地静态/呈现别名 | 新增本构、状态、控制算法后仍称纯 LU；修改安装的 MSL 源文件 | MSL 自己的内部结构原样保留，不强制展开/复制 |

**不要把“需要两个子实例”理解成拆碎任务。** 一个系统可以直接使用单个内聚行为，不必先包一个 AB。确有安装、接口汇聚或替换责任的单实例包装可以按 SB 或相应呈现别名描述；没有新增边界价值的包装建议简化。不能为符合数字放一只无用探头。已认可工程的角色登记与源码修改分开：更准确的分类不等于授权重构。

## 2. 白箱公共语法逐项清单

以下适用于 **全部 TB/SB/AB**。Modelica 语言本身允许的写法，仍可能不适合 MOSAIC 白箱；不要把工程分工限制说成语言语法错误。

| 内容 | 白箱可以有 | 白箱不应有 | 检查重点 |
|---|---|---|---|
| 名称与注释 | 合法自然类名、简短类说明、必要字段说明 | 仅靠 TB_/SB_/AB_ 前缀认定角色 | 类身份不随显示语言变化 |
| 配置声明 | parameter、constant、parameter record；必要 package/type 引用 | 将普通运行 record/Real 当作一组隐藏在线状态 | 同一数据记录作静态配置还是在线信息须明确 |
| 静态计算 | `parameter Real area=width*height`；仅由静态输入决定的纯函数调用 | 用 time、运行输出或在线文件生成设计值 | 分项与派生值不能成为两份独立权威输入 |
| 子实例参数 | `device(capacity=cfg.capacity)`；公开 start/fixed/initType 的静态设置 | `device(u=source.y)`；`device(u=1)` 这类运行输入绑定 | 参数 modifier 与输入变量 binding 是两件事 |
| 公开端口 | MSL 或已定义的项目 connector；固定尺寸数组 | 普通输出变量被当作可连接端口；深层私有量别名 | 公开不等于 connector；按实际声明核对 |
| 连接方程 | `connect(a,b)`；固定维数整数组连接 | `y=a+b`、`p=k*flow`、`state=time>...` | `equation` 关键字本身不是违规 |
| 静态连接展开 | 仅含 connect、由参数/固定维数决定的 for/if 连接模板，展开后拓扑确定 | 循环中混入赋值/本构；以在线状态改变连接拓扑 | 建议发布常用构型时显式展开；允许模板不代表允许隐藏行为 |
| 条件组件 | 仅在已声明静态构型中采用，并能证明每个发布构型输入、参考与状态闭合 | 依赖运行量创建/销毁组件；未验证分支留作“自动可用” | 建议优先同接口的 replaceable/redeclare；不把条件分支从检查范围丢掉 |
| 算法 | 本层无需算法段 | algorithm、initial algorithm，包括“只做一点转换”的算法 | 算法进入 BU 或标准块 |
| 连续/离散状态 | 状态存在于所声明的子 BU/LU | 本层 der、when、pre 驱动记忆、reinit | 每个状态的所有者清楚 |
| 初始化 | 配置状态拥有者的公开初始化参数 | 本层 initial equation 给子状态补条件；覆盖孙级隐藏初值 | fixed/guess/steady-state 不混用 |
| 求和/缩放/查表 | 显式实例化所需 BU/LU 并连接 | 把一行换算、选择、限幅当“胶水”留在盒内 | 行数短不意味着没有行为 |
| 常量运行源 | Constant/BooleanConstant 或内聚项目源，再 connect | 用常量右端直接绑定子输入，以为这是配置 | 输出常量也是运行信号来源 |
| 断言与终止 | 离线配置检查；子行为单元内部有理由的运行诊断 | 本层在线 assert/terminate；用断言凑初始化 | 真实保护与辅助诊断有不同用途 |
| 继承 | 零行为模板；或有效展开后仍是可导航纯连接结构的白箱基类 | 继承控制律/积分器后仍称白箱；只看当前文件判零行为 | 检查 extends、redeclare 和修饰后的有效实现 |
| 替换点 | 静态、接口相容的 replaceable/redeclare | 运行时改类；新角色突破父层责任却不更新映射 | 调整角色元数据不强制改自然类名 |
| 上下文 | 正确作用域的 inner world/system；outer 引用 | 可变全局上下文承担隐式在线数据交换 | outer 不重复实例化物理对象 |
| 图形与说明 | Icon、Diagram、Placement、Line、Documentation、Dialog；实验入口的 experiment | 在显示表达式中实现隐式控制，或访问未登记的深层变量 | experiment/Evaluate 等不能在辅助差异检查中全部豁免 |

相较于早期版本，本版把“所有静态结构 for/if 与继承都一律禁止”的机械限制，细化为**有效实现是否只声明、配置与连接**。固定连接模板可以使用，但发行构型应可展开、可导航且输入闭合。普通行为分支、动态绑定和本层初始方程仍然禁止。此项只定义当前规范的允许边界，不授权自动修改已认可工程的行为。

### 2.1 参数配置与运行绑定：最容易混淆的三行

```modelica
// 合适：gain.k 是参数；源与增益通过真实端口连接。
parameter Real scale=2 "静态比例";
Modelica.Blocks.Sources.Constant source(k=1);
Modelica.Blocks.Math.Gain gain(k=scale);
equation
  connect(source.y, gain.u)
    annotation(Line(points={{-60,0},{-20,0}}, color={0,0,127}));

// 不作为白箱写法：u 是运行输入，不是参数。
// Modelica.Blocks.Math.Gain gain(u=source.y);
// Modelica.Blocks.Math.Gain gain(u=1);
// equation outputValue = scale*inputValue;
```

前两种运行输入绑定在相应上下文中可能是合法 Modelica；MOSAIC 不采用它们，是为了让上层交互在端口与 Diagram 中可见，而不是把它们错误称为语言不合法。

### 2.2 真正的父边界转发

```modelica
model SignalSystem "信号处理系统"
  parameter Real k=1 "比例参数";
  Modelica.Blocks.Interfaces.RealInput u "公开输入"
    annotation(Placement(transformation(extent={{-120,-20},{-80,20}})));
  Modelica.Blocks.Interfaces.RealOutput y "公开输出"
    annotation(Placement(transformation(extent={{80,-10},{100,10}})));
  Modelica.Blocks.Math.Gain gain(k=k)
    annotation(Placement(transformation(extent={{-20,-20},{20,20}})));
equation
  connect(u,gain.u)
    annotation(Line(points={{-100,0},{-24,0}},color={0,0,127}));
  connect(gain.y,y)
    annotation(Line(points={{22,0},{90,0}},color={0,0,127}));
end SignalSystem;
```

这是说明公开边界和参数分配的语法示例，不是声称已在本环境完成编译的整机工程。实际发布还按用途补齐系统图形与证据。不能把 `y=gain.y` 作为偷懒的白箱转发，也不能将 `gain.internalState` 直接接到外部。

## 3. TB：完整仿真实验入口

**必须有的内容。** TB 明确一次实验研究什么、从哪个生效配置启动、外界条件来自哪里。所有必须的因果输入有来源，物理参考和上下文闭合；状态初值通过所属子单元的公开配置给出。TB 不参与另一 TB 作为功能设备。

**允许的构成。** 对象系统、环境/工况、任务请求、必要负载、上下文、观测显示可直接放置。它们是否各占一个模型由真实职责决定；已有内置任务管理可留在系统内部。一般用 `model` 表达完整实验，使用 `experiment` 设置声明实验范围；并行试验通过独立入口复用同一个系统类。

**禁止的混入。** 不在 TB 中写飞行动力学、轨道传播、热平衡、控制器积分、任务状态机或结果 KPI 的运行算法。不为得到更多曲线再实例化第二套电池/动力学。参数展示不通过动态方程生成另一组当前参数；结果导出不需要新增物理监视系统。

**建议的文档。** 写用途、入口、有效配置、任务起止与主要输出导航；统一工具操作放项目根说明。不要每个子类都重复仿真窗口的点选教程。

**检查卡。** 查看 TB 声明与 connect，确认对象和边界闭合；查 `inner` 持有者；检查起止时间与真正任务相符。编译后是否完成仿真是单独状态，不由 TB 文件存在判定。

## 4. SB：系统、分系统与集成边界

**必须有的内容。** 对应一个真实组成或清楚的集成责任；公开所需物理/信息端口；向子实例传入静态设计配置；通过 connect 组织网络。系统对外只暴露需要的边界，不要求公开所有局部计算量。

**允许的构成。** SB 可以包含 SB、AB、BU、LU，也可以直接由一个合适行为单元实现当前系统的降阶行为。必要 world/system 由最近共同作用域持有。把多路标准接口组合成有固定成员的项目端口是允许的，但字段合同必须清楚。

**禁止的混入。** 不以 `system`、`controllerSystem` 名称掩盖本层计算。求和、单位转换、选择、滤波、采样和计时均由对应行为/库单元承担。不跨层读取孙级隐藏状态，不把连接图与另一套后台运行结构分离。

**建议的边界设计。** 先从实际组成分解，再按需要建立共享电源、热或信息网络；不要先创建四域模板再塞设备。对外端口稳定，内部细化尽量不影响上级；必要静态参数可以集中到一个 record，但不创建隐式可变总线。

**检查卡。** 选一条典型输入到实际作用再到输出的路径，逐层可追溯；子实例与图中设备对应，行为没有停留在本层。单实例包装是否值得保留是设计判断，不是自动删类命令。

## 5. AB：末级黑箱装配

**必须有的内容。** AB 是多个有实际职责的 BU/LU 的局部装配，公开共同边界，参数集中分配，本层只连接。端口转发和参数记录本身不充当第二个功能单元。

**允许的构成。** 热容＋热导、控制算法＋限幅＋显式信号源、储能元件＋电路支路＋测量等可以组成 AB。标准库元件内部具有层次，不因此破坏 AB 的末级性质。

**禁止的混入。** 不能在 AB 中一面装配组件，一面自己继续积分同一状态或补本构。需要组织下一级装配/系统时，应把当前边界按 SB 描述，而不是增加空壳或改前缀蒙混。仅静态装配某单元的包装，不应假称已拆出多个行为。

**建议的拆分粒度。** 一组经常一起替换、需要共同理解的末级实现作为装配；一行无需独立工程身份的纯函数不必拆成文件。一旦有多个独立运行块，就明确列出它们，而不是藏进名为 Core/Bridge 的 BU；接口整合也不能成为新建“大 BU”包装原系统的理由。

**检查卡。** 列出直接运行子实例；排除 record、type、纯函数、接口和 outer 引用。对每个子实例说明它为何存在。不得把“子实例越多”当作建模越完整。

## 6. BU：本构、算法和局部状态拥有者

**必须有的内容。** BU 有内聚职责、明确接口、需要的参数、内部变量、方程/算法及初始条件。它可以是 `model`，也可以在合适的因果信号语义下是 `block`。职责决定角色，语言关键字不决定角色。

**允许的内容。** 代数方程、微分方程、合法离散事件、状态机记忆、必要断言与终止、纯函数调用、参数记录、类型和连接器声明。一个刚体的多个坐标、一个算法的多个记忆可以由同一 BU 持有；规范不限制为“一个 BU 只能一个状态”。

**禁止的内容。** 任何 connect，包括逐成员连接、接口转发及继承而来的连接；同时禁止独立运行 model/block 子实例，包括 MSL PID、Limiter、CombiTable、传感器和热容。需要这些块时采用 AB/SB 装配；查表本身也可由纯函数在 BU 内计算。不得偷偷访问其他单元的内部状态或实现第二套真实库存。

**接口与状态。** 不用于外部合同的实现变量建议 `protected`；既有合法公开诊断可以保留，但消费者身份明确。输出方程在 BU 内合法；不能为了结果栏注释新增输出方程。状态初值的固定、猜测、稳态或离散 pre 责任都在此落实。

**数值与边界。** 写清真实工作域和数值延拓；normal limit 不冒称安全保护。`noEvent` 只抑制相应事件，不意味着连续可微；`smooth` 不得虚报。参数 `min`/`max` 是约束信息，不等于写好了运行限幅。

**检查卡。** 读实际方程和算法，再查本类与 extends/redeclare 后是否带入 connect 或运行子实例。声明单一职责但同时做环境、控制、积分、显示四类工作的“大核心”不宜作为示范。辅助维护任务只记录这种结构事实，不擅自拆改。

## 7. LU：原生标准库与静态别名

**必须保持的内容。** 原 MSL 类身份、参数意义、接口、内部状态和本构。直接复用无需复制源代码；仅做静态参数或图形呈现的本地别名仍可作为 LU。原始库内部结构不受项目“BU 无 connect、无独立运行子实例”的限制；这不授权修改安装的 MSL。

**可以做的内容。** 固定公开参数、配置公开初值、redeclare 合同允许的介质，设置实例 Placement。原图标通常保留；MSL 接口和派生接口的连接线使用原生默认色。传感器同其他库元件一样允许直接使用。

**不可以仍称纯 LU 的内容。** 新增本构、运行输入绑定转换、输出计算、状态或改变参数含义。此时按有效实现形成 BU 或显式装配，必要时保留原 MSL 组件作为其子单元。纯图形替换不是新增物理能力，不能借别名掩盖依赖变化。

```modelica
// 未改行为的 MSL 参数配置别名：可以按 LU 理解。
model ThermalMass "集总热容"
  extends Modelica.Thermal.HeatTransfer.Components.HeatCapacitor(C=1200);
end ThermalMass;

// 若另外添加运行状态或新的温度计算，就不再只是呈现别名。
// 不应为了输出注释重定义继承状态；在已有声明/结果合同中处理说明。
```

**检查卡。** 对照实际 MSL 路径和静态 modifier；不存在的端口不因名称像 `flange` 就当作可连接。原 MSL 版本、来源和许可保持，不能全局替换 `version`。

## 8. 支撑类：不是第六套物理模型

| 类种类 | 应有内容 | 不应有内容 | 文档应解释 |
|---|---|---|---|
| `package` | 职责清楚的类组织、必要 import/type/constant、子包和加载顺序 | 把包名当运行实例；为文件分类创建空执行网络 | 包用途、主要入口、下级类去哪里找 |
| `record` | 类型明确的字段、单位、默认或派生关系；配置使用时以 parameter 持有 | 将配置 record 当未声明的在线共享状态；多份权威默认值 | 每组字段意义、消费者、编辑源、生成关系 |
| `type` / 枚举 | 基本类型、单位或码表；稳定编码语义 | 同一整数在不同端含义不同；把视觉标签作协议值 | 单位/范围/每个枚举项含义 |
| `connector` | 明确的 potential、flow、stream、input/output、字段维数及图形 | 设备本构、积分器、控制算法；为换色改守恒关系 | 成员、方向、单位、时间、介质/坐标、适配边界 |
| `function` | 明确输入输出、局部变量和合法函数算法；纯计算优先 | 在线文件读写、联网或副作用被当纯函数；借函数隐藏独立仿真对象 | 参数顺序、返回值、有效域、异常/超界策略 |
| `partial` | 被复用的接口、参数或部分行为合同；明确尚缺什么 | 直接作为最终可运行设备；父白箱不审查继承来的行为 | 由派生类补齐的内容与可替换边界 |
| 介质包 | 与选用 Fluid 组件相容的状态、物性函数和基准 | 为通过接口检查悄悄借用无依据的物性；不同 Medium 混接 | 支持物性、近似、单位、焓/内能参考及未支持功能 |
| 图形/说明资产 | 原生图元、已认可品牌图、合法离线路径、必要说明 | 必须导入的额外物理库；运行期间写文件来刷新图形 | 实际使用处、可编辑源、跨工具显示已查/未查 |

## 9. 按功能落实到角色，不发明新的“万能桥”

| 功能 | 实际推荐归属 | 责任底线 |
|---|---|---|
| 环境与外界条件 | 单一环境 BU，或由多个环境单元构成的 SB | 时间/空间基准清楚；简化边界不冒称未实现的反作用 |
| 任务时序与自主任务管理 | BU；多单元规划可由 AB/SB 组织 | 请求与实际完成分离，任务状态有唯一所有者 |
| 控制器 | BU 方程实现或 AB 标准块装配 | 合法反馈、积分与饱和处理、初始化与切换一致 |
| 传感器 | 原生 MSL LU、项目 BU 或带调理的 AB | 安装位置、零/实际负载和时间语义明确 |
| 无状态单位转换/编码映射 | 内聚 BU、标准转换 LU；多个块形成 AB | 维数/单位/码表明确；不能留成白箱里的胶水方程 |
| 运行显示 | 无状态 BU/LU，或只读展示装配 | 读数与诊断身份明确，不再积分真实库存 |
| 参数面板 | 引用同一配置的展示 | 不产生新默认值，不是运行时物理参数控制器 |
| 协议/遥测汇聚 | 具名 connector＋所属 SB/AB 中的真实分接；仅实际编码/单位变换使用 BU/LU | 整体总线和 MSL 类型成员分别追溯；不隐式扩展字段 |
| 初态求解 | 公开配置＋状态拥有者初始化；必要离线准备 | 固定、猜测、稳态约束分开，不由上层强制状态 |

**角色检查的结果不应简化为“类名前缀正确”。** 最小检查记录应包括：类路径、概念角色、直接功能子实例、继承来源、本层是否有行为、状态所有者、接口合同、图形入口与未解析项。工具不能解析的继承/重声明必须列出，不能靠未发现问题冒作完整符合性。


## 10. 复用选择与禁止的接口捷径（v0.9）

架构优先采用多 SB＋多 AB＋多 LU＋尽可能少 BU。这里的“多”和“少”是组织方向，不是最小组件数量、固定占比或新的考核数字。标准组件已能完成的求和、查表、限幅或测量，优先复用；内聚且不能合理再分的机制及必要数据转换再采用 BU。

白箱可以直接连接复合接口，并在内部将其所需成员连到 MSL 标量端口。它不必为每个字段增设一次对外标量口，也不必要求每个接收设备消费全部字段。传递、组装、单位换算分别判断：同语义传递使用 connect；改变值的换算进入 BU/LU；多个运行单元的装配仍是 SB/AB。

**明确否决三种捷径。** 白箱用等值绑定代替连接；BU 内部用 connect 整理总线；把原本多层系统、标准库组件和测量链塞进大 BU，外面仅剩一条总线。三者不因界面线少而成为合格实现。源文件中出现角色违规时，改标签不能替代修复；未获行为改造授权则记录待改项，不对该项填写通过。
