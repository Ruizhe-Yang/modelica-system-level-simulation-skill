# 接口、配置与结果的最小合同表

“有合同”不等于建立一套庞大平台。下列字段可置于源码、简表或项目记录中；同一个事实只有一份权威维护位置，其他说明引用它。

## 1. 端口与信号成员

| 字段 | 最少说明 | 例子 |
|---|---|---|
| PortID / 端口路径 | 稳定身份与所属类，实例路径另登记 | spacecraft.environment |
| 类型与来源 | 原生 MSL、MSL 派生、自定义整体或自定义成员 | DerivedHeatPort → HeatPort_a |
| 量义与单位 | quantity、内部单位、显示单位或码表 | 温度 K；显示 °C |
| 维数与结构 | 数组长度、字段列表，复合接口是否固定 | 三维向量；每路电源供回 Pin |
| 因果/守恒 | input/output 或 potential/flow/stream | Q_flow 向组件流入为正 |
| 参考与物性 | 坐标系、介质、焓/内能零点等 | 惯性系/本体系；同一 Medium |
| 时间 | 连续、离散、采样、保持、延迟、有效位 | 连续读数而非一秒采样 |
| 生产消费 | 唯一源、使用者、边界转发位置 | 测量链 → 控制；诊断 → 离线 |
| 图形策略 | 派生来源或自定义主色；真实连接点 | MSL 热接口线色191,0,0 |

**接口整体与字段不是同一层。** 一个自定义 PowerPort 内含 MSL 电气 Pin，不能因为外壳是橙色就把所有 Pin 的线改橙；一个青色信息总线包含 RealInput，成员连接仍按 Real 类型处理。颜色核对与类型/守恒核对并行，颜色正确不能证明物理连线正确。

## 2. 状态所有权

| 字段 | 应登记内容 |
|---|---|
| StateID / 物理意义 | 哪份真实库存、运动自由度或算法记忆 |
| Owner | 实际 BU/LU 实例；不是只写上级系统名 |
| Equation / Update | 连续导数或离散更新的实际实现位置 |
| Initialization | 参数来源；fixed/guess/steady-state/pre 的定义 |
| Reset / Re-entry | 何时允许复位，依据是什么，任务重入如何连续 |
| Observation | 公开测量、诊断或估计路径；不新增第二份状态 |

## 3. 参数与曲线

| 类别 | 权威内容 | 不当替代 |
|---|---|---|
| 标量设计参数 | ID、值、单位、类型、范围、可编辑性、消费者 | 从只读面板复制第二份默认值 |
| 任务/初态 | 时域、阶段、目标请求、初始库存、环境场景 | 用预计算的实际轨迹直接驱动真实状态 |
| 一维曲线 | 严格递增 x、有序两列值、单位、域与插值 | 使用节点序号代替非均匀横轴 |
| 二维矩阵 | 行轴 x、列轴 y、完整网格、单位和支持域 | 轴翻转但仍引用同一份消费者解释 |
| 生成快照 | 固化后的 record/数组/常量与来源身份 | 只生成文件但参数未进入方程 |

## 4. 结果与验收

| 字段 | 应登记内容 |
|---|---|
| SemanticID / Path | 稳定语义ID、原始结果路径、别名适配 |
| Description / Unit | 可读说明与单位，不靠额外变量生成中文标签 |
| Identity / Time | 真值、测量、估计、命令、诊断；时序及所需分辨率 |
| Required / Purpose | 是否必须保存，用于哪项任务或诊断 |
| Window / Metric | 起止事件、平台时窗、峰值/积分/均值口径 |
| Evidence | 真实 RunId、原始文件、源码与配置、引擎 |
| Status | 运行、读取、指标、外部验证分别给状态 |

工具发现一个变量名称，不等于变量轨迹完整；一个输出恒为零可能是合法任务状态，也可能是输入/结果/模型问题，需要按事实逐层排查。缺数据不以零填充。
