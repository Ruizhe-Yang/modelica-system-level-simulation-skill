# MOSAIC v0.8｜Modelica 总体建模规范

**Model the Whole as MOSAIC.**

M01—M36 是当前生效主条文，26 项必须、9 项建议、1 项参考。角色详细合同见 [model_roles.md](model_roles.md)，接口与字段见 [interfaces_contracts.md](interfaces_contracts.md)，旧条号去向见 [traceability.md](traceability.md)。M05/M08 恢复明确的角色与有效实现边界；不据此授权修改已认可工程的行为。

## M01｜规范用途与依赖边界 · 必须
MOSAIC 是 Modelica 总体工程的建模规范。它规定模型如何分层、放置行为、定义接口、传递配置和维护交付，不是必须加载的 Modelica 基础库。标准交付以项目自有源码和 MSL 4.0.0 为依赖基线；已有项目冻结的版本不自动升级。

### 应包含 / 应落实
- 工程根包、主入口、MSL 精确版本、必要资源和依赖清单。
- 设计用途、包含与未包含的过程；外部环境与被研究对象的边界。
- 已生成的本地配置与曲线，使模型加载不依赖先运行办公软件。

### 不应这样处理
- 为了使用规范创建空的 MOSAIC 运行库；暗中增加专业库、FMU、在线 Python 或联网物理求解。
- 将额外集成默认算入标准配置。确需外部实现时单独批准扩展配置，登记依赖与作用，不声称满足标准依赖配置。

**核对方式：**从实际加载入口核对依赖与必要资源；核对 uses 声明和真实库版本，而非仅查看版本文字。

**示例：**12UCubeSat 的离线环境数据是准备阶段资产；仿真读取固化在 Modelica 中的数据，不在积分时重新执行环境生成脚本。

**来源与修订依据：**P01 G01；P02 M01/M20；P04 M01

## M02｜自然命名与一次性显示 · 建议
类名建议采用实际系统、部件或职责名称，TB、SB、AB、BU、LU 是概念，不是命名前缀制度。代码标识符、类说明、图标文字、稳定数据 ID 分别维护。

### 应包含 / 应落实
- 例如 CompleteMission、SpacecraftSystem、ElectricalPowerSystem；单位符号、通用缩写和已有根包可以保留。
- 模型树已显示英文类名时，string-comment 只填写中文用途；显示成“英文类名（中文用途）”。
- 目录、within、package.order 与引用的语言一致性仍属于必须满足的工程完整性。

### 不应这样处理
- 在类说明中再次写“ClassName（中文）”，造成 ClassName (ClassName（中文）)。
- 为显示名称改动而修改类标识符、结果变量路径或矩阵 ID；批量无上下文去前缀。

**核对方式：**分别检查源码声明和目标建模器模型树，不把 HTML 标题的排版规则直接套到类的 string-comment。

**示例：**推荐声明 model CompleteMission "完整任务仿真"；类路径仍是 OneSatSim.Simulation.CompleteMission。

**来源与修订依据：**P02 M02/M32；P05 命名修订

## M03｜多视图只使用一套执行对象 · 必须
结构视图、物理域视图、工作视图和观测视图应映射到同一批实例及连接。视图是理解工程的方式，不是再建立一次物理系统。

### 应包含 / 应落实
- 真实系统组成到模型实例的映射；一个发布配置的确定入口。
- 跨系统能量、物质、运动和信息关系；必要共享网络的实际职责。
- 不同试验可以复用同一个系统类，但每次试验的独立实例与初态要清楚。

### 不应这样处理
- 在“结构图”和“工作图”中各放一份电池、刚体或数据队列，并同时参与总体积分。
- 没有对应物理域仍为凑模板建立电、热、力、信息四套空网络。

**核对方式：**对照实例路径和状态所有者确认没有重复库存；不同视图的连接语义一致。

**示例：**立方星的电源、热、结构和信息视角可以同时解释同一航天器；不复制另一套航天器来画工作视图。

**来源与修订依据：**P02 M03；P04 M03

## M04｜可导航的真实组成与拓扑 · 必须
系统和装配的实际组成应能通过原生 Diagram 导航，图形中的连接必须与 connect 对应。图上的位置不是物理安装位置，装饰线也不是连接方程。

### 应包含 / 应落实
- 实际功能子实例、公开端口及必要的 Placement。
- 实际 connect 的 Line，以及能对应真实端口的可辨端点。
- 与职责一致的环境、对象、任务和观测边界。

### 不应这样处理
- 只有画线没有 connect；通过改 connect(a,b) 的端点来修复图形错位。
- 为了画布整齐删除接口、合并真实库存，或用无关联线冒充耦合。

**核对方式：**从源码声明和 connect 枚举检查对象，不只检查已经存在的图形注解。色号、线宽和布局偏好另按 M33；连接事实不能用美术评分替代。

**示例：**SpacecraftSystem 的环境口、总体网络和分系统实例来自实际声明；改变图标位置不改变质心位置和物理安装参数。

**来源与修订依据：**P01 G32/G93—G95；P02 M04；P04 M04

## M05｜五种模型角色与包含关系 · 必须
TB（顶层盒）、SB（系统盒）、AB（装配盒）均属于白箱；BU（项目行为单元）与 LU（MSL 复用单元）向上层提供黑箱边界。角色按职责和有效实现判断，不按文件名或图标判断。

### 应包含 / 应落实
- TB：完整仿真入口；SB：系统或集成边界；AB：末级黑箱装配。
- BU：内聚本构或算法；LU：未经行为改变的 MSL 原组件或静态/显示别名。
- TB/SB 可直接使用 SB、AB、BU、LU；AB 的直接功能子单元为 BU/LU；BU 不隐藏独立运行子组件。

### 不应这样处理
- 把包含运行方程的类直接称为白箱；把继承进来的运行结构当作不存在。
- 为凑层级或子实例数添加空盒、无用常量、重复探头；将 package 当作运行盒。

**核对方式：**先列实际子实例与继承链，再按本章角色合同分类。新建工程按此组织；维护已认可工程时可在映射中校正角色，不因类别名而擅自修改已验证行为。

**示例：**CompleteMission 是 TB；SpacecraftSystem 是 SB；包含热容与热导的局部组合可归 AB；纯查表函数不计为 AB 的第二个设备。

**来源与修订依据：**P01 §02；P02 M05；P05 细化要求

## M06｜按依赖清理无用资产 · 建议
建议精简不服务声明入口、发布配置及其支撑工作的自有运行模型。清理依据是完整依赖，而不是顶层是否直接放置。

### 应包含 / 应落实
- 实例、extends、replaceable/redeclare、函数、类型、参数记录、资源和生成器引用。
- 其他合法配置、必要局部试验、授权保留项及历史资产的区别。

### 不应这样处理
- 按文件名或目录批量删除；把无物理方程的记录、图标或数据当作无用。
- 无证据删除尚未证明不可达的类或跨目录链接目标。

**核对方式：**列候选、引用证据与归属再清理。未清理不自动否决主规范；删除破坏加载则违反 M01/M31。

**示例：**某太阳阵类没有出现在总体入口中，并不排除其被分系统、继承配置或生成器引用。

**来源与修订依据：**P02 M06；P04 M06

## M07｜白箱本层只声明、配置和连接 · 必须
所有 TB/SB/AB 使用同一白箱规则：本层只声明静态配置、真实子实例、公开端口和必要上下文，并通过 connect 组成网络。equation 段可以存在，里面不能混入本层本构或控制行为。

### 应包含 / 应落实
- parameter/constant、parameter record、静态维数和纯函数静态参数计算。
- 公开 connector、允许的子角色，以及直接或静态可展开的 connect。
- 对子单元公开参数及公开初始化选项的静态 modifier。

### 不应这样处理
- 普通运行等式、der、when、reinit、algorithm、initial equation/algorithm、在线 assert/terminate。
- 运行输入绑定 child(u=source.y)、输出别名 y=child.x；即使输入绑定右侧是常量也不是参数配置。
- 隐藏计算的 extends、动态 modifier 或图形显示表达式；用白箱初始方程补救错误初始化。

**核对方式：**覆盖本类、继承、重声明、绑定和 modifier；不展开审计子黑箱本构为白箱行为。具体语法逐项表、静态连接循环边界与反例见下文。

**示例：**connect(controller.y, heater.u) 是装配；heater.u = gain*controller.y 是行为，应在增益/控制单元中实现。

**来源与修订依据：**P01 §03/G08—G10；P02 M07；P05 白箱细化

## M08｜行为单元与库复用的边界 · 必须
BU 负责一项内聚物理或计算行为，可有多个属于同一对象的状态；其有效实现不包含独立运行 model/block 子实例。LU 保留 MSL 原类实现，其库内部层次不必展开为项目源码。

### 应包含 / 应落实
- BU 的公开接口、参数、内部量、方程/算法、必要初态和适用域。
- LU 的实际 MSL 路径、版本、静态修饰与未改变行为的说明。
- 纯函数调用、record/type/connector 不计为运行子实例。

### 不应这样处理
- 把 PID、CombiTable、Integrator 或传感器子实例藏在 BU 中却声称是纯行为叶子。
- 扩展本构、增加状态或输出计算后仍称为仅呈现的 MSL 别名。
- 为了满足叶子形式复制整个 MSL 或破坏现有可用传感器。

**核对方式：**按有效实现归类：纯连接组合是 AB/SB；单一方程实现是 BU；原生库复用是 LU。分类调整不等于授权物理重构，复制代码需保留许可。

**示例：**直接使用 MSL HeatCapacitor 是 LU；自己的集总热容方程是 BU；二者与热导、探头组成的显式局部网络是 AB。

**来源与修订依据：**P01 G18/G90—G92；P02 M08；P05 细化要求

## M09｜逐层公开端口与上下文 · 必须
在线交互通过本层公开端口或直接子实例的公开端口。跨系统连接由最近公共父层组织，中间层逐层转发；普通公开变量不自动等于可用于 connect 的 connector。

### 应包含 / 应落实
- 接口转发路径、唯一来源及合法消费者。
- 需要的 inner world/system 在正确作用域持有；outer 只引用，不成为另一个物理实例。
- 静态公开参数配置与运行反馈访问分别检查。

### 不应这样处理
- 父层读取孙级私有状态后伪装成传感反馈；跨层直接接内部元件。
- 使用可变全局 record/上下文作为隐式数据总线；给同一运行量第二次赋值。

**核对方式：**从每条端到端关系展开直接端口路径；核对 inherited 接口和可见性。离线读取已保存内部诊断不属于在线穿透。

**示例：**总体经 spacecraft.onboardTelemetry 取得遥测；不因显示需求在顶层读取电池内部积分器，再新增状态别名。

**来源与修订依据：**P01 G11/G15；P02 M09

## M10｜保留物理与信息接口语义 · 必须
按交互本质选择接口。物理端口保留非因果、flow/stream、参考系及守恒意义；信号端口保留生产者和时间意义。连接本身不产生阻抗、容积、延迟或损耗。

### 应包含 / 应落实
- 电、热、转动、平动、流体和三维框架等所需接口；标准类型优先。
- 转换器、执行器与传感器等跨域作用的明确实现。
- 自定义降阶接口的守恒范围、反流能力、物性和省略项。

### 不应这样处理
- 为减少线数或统一颜色，把需要守恒的物理口全部改为 RealInput。
- 按 a/b、正负符号或图形箭头推断真实流向；把不同域直接连在一起。

**核对方式：**检查连接变量、符号、介质与参考系。Q_flow 已是热功率；转动功率是转矩乘角速度，不是转矩乘角度。

**示例：**电源复合接口可以包含多路 MSL 电气 Pin；整体打包不改变每路供回电流关系。

**来源与修订依据：**P01 §04；P02 M10；T02 MSL 4.0.0

## M11｜每个接口都有可核对的合同 · 必须
端口合同至少明确含义、类型、单位/码表、维数、因果或非因果性质、正方向、时间、来源与消费者；物理接口另明确介质和参考基准。

### 应包含 / 应落实
- 每个必须输入的真实来源或显式默认源；未用输出的用途。
- 复合接口的实际成员字典；可扩展接口的本次实际字段。
- 连续、事件、采样、延迟、有效位及初始化语义。

### 不应这样处理
- 同名字段被当作兼容证据；Pa 与 bar、角度与弧度混连。
- 一个因果连接集有多个有效驱动者；用隐式新字段绕过合同。

**核对方式：**对照声明和实际 connect 核对，不凭目录名猜端口类型。父边界转发不增加新生产者；物理开路、自由或绝热边界按本域语义判定。

**示例：**遥测“温度”还需标明是哪个部件、K 或 °C、物理真值还是探头读数，以及是否带采样保持。

**来源与修订依据：**P01 G12—G14/G118；P02 M11

## M12｜状态、库存与初态唯一负责 · 必须
每份真实质量、能量、运动自由度、数据库存和软件记忆由一个责任实现持有。初态在拥有状态的 BU/LU 内实现，上层通过公开配置设置。

### 应包含 / 应落实
- 状态含义、量纲、所有者、初始化来源和合法复位条件。
- start 猜测、fixed 固定、稳态约束及离散 pre 初值的区别。
- 估计状态与真实状态分开标识。

### 不应这样处理
- 在电池、监视器和显示面板分别积分同一 SOC；重复计算同一库存。
- 白箱 initial equation 强制孙级隐藏状态；全部变量 fixed=true 导致过约束。

**核对方式：**核对状态所有权表与当前方程/算法，连续与离散赋值不冲突；静态 der 数量不冒称编译后状态数。

**示例：**热容唯一持有温度；测温通道可以有自己的滤波状态，但该状态不是第二份热储能。

**来源与修订依据：**P01 G09/G19/G123；P02 M12

## M13｜指令、实际作用和有限能力分开 · 必须
任务请求和控制指令不直接指定真实物理状态，也不代替能量来源。保留当前用途需要的惯性、库存、损耗、饱和与反作用。

### 应包含 / 应落实
- 请求值、执行器实际值、读数和完成状态的独立语义。
- 电力、热、转矩、物质与数据的有限供给/吸收能力。
- 任务重入沿用当前库存和热状态。

### 不应这样处理
- 直接令真实姿态/转速/温度等于参考值，声称已实现闭环动态。
- 把 min/max 属性当作已实现限幅；无依据重置燃料、热量或电量。

**核对方式：**沿指令到实际作用再到反馈的路径核查。简化模型可使用明示的理想边界，但不能冒称尚未建模的有限能力。

**示例：**加热命令需通过负载/热源形成热流；电源不可用时不能仍记为已供能的有效加热。

**来源与修订依据：**P01 G20/G69；P02 M13

## M14｜控制转换、记忆与时序一致 · 必须
模式码、进入时刻、激活条件、最小驻留、迟滞和执行接管应有明确定义。转换使用一致的事件前状态，不跳过真实需要的等待过程。

### 应包含 / 应落实
- 转移条件与设备实际能力相容。
- 积分器饱和、跟踪、前馈和执行器已有作用在切换时一致。
- 正常限制与专门安全保护声明分别说明。

### 不应这样处理
- 同一算法中先改状态再用旧进入时刻连续跳过驻留。
- 只看稳态均值，遗漏切换峰值或失败工况；把正常控制称为已认证保护。

**核对方式：**按项目必要转换逐类检查，保留初态、进入条件、全过程量和失败状态；不强制所有工程采用同一状态机库。

**示例：**进入成像模式须满足任务与供电条件；发出模式请求不等于载荷已进入工作状态。

**来源与修订依据：**P01 G109—G113；P02 M14

## M15｜命令、测量、估计和诊断有身份 · 必须
反馈控制读取已声明可得的测量、状态和估计；内部守恒使用物理真值。工程显示可展示测量或诊断，但必须清楚标识来源，不能把真值改名就称作传感器。

### 应包含 / 应落实
- 输入参考、实际状态、理想/非理想测量、估计和只读诊断的区分。
- 理想采集具有明确职责和公开路径，即使数值等于真值。
- 物理耦合不经采样/滤波量代替守恒量。

### 不应这样处理
- 未声明内部真值绕过传感/估计链进入控制器。
- 将命令标志当作真实完成，或把未来数据引入在线决策。

**核对方式：**对信号成员逐项记录身份与使用者；显示身份标注可以简洁，不要求为所有诊断增加一只传感器。

**示例：**遥测中可同时保存载荷命令和载荷实际状态，二者用于不同问题，不合并成“工作完成”。

**来源与修订依据：**P01 §06；P02 M15；P04 M15

## M16｜传感器来源按实际需要选择 · 建议
允许直接使用 MSL 传感器；有定制动态、安装接口或复用收益时，可采用项目自有传感器。实现来源是选择，不是强制本地化任务。

### 应包含 / 应落实
- MSL 原传感器及其未改行为的静态别名。
- 有明确偏置、滤波、采样或安装模型的项目传感器。

### 不应这样处理
- 仅为规范合规复制 MSL 传感方程；批量替换已有效工作的测量链。
- 没有实际安装和输出合同，仅换一个传感器图标冒充已测量。

**核对方式：**来源选择不改变 M11/M15/M17。凡复制源码，保留许可；用户没有噪声/故障研究需求时不自动加入。

**示例：**热系统可直接采用 MSL TemperatureSensor；自定义测温通道同样可以保留。

**来源与修订依据：**P02 M16；P04 M16

## M17｜测点位置、物理负载与采样真实 · 必须
每条测量链明确被测部位、物理量、安装方式、探头、必要调理和消费者。探头的反作用以及时间特性按当前模型说明。

### 应包含 / 应落实
- 电流/热流探头的串联位置与电压/温度探头的并联或取样位置。
- 理想零负载或真实负载；滤前/滤后及参考坐标。
- 模拟动态、采样保持、控制周期、通信和存盘间隔分别定义。

### 不应这样处理
- 一秒存盘被写成一赫兹传感采样；内部可观测量被计为实物已安装测点。
- 在守恒链中用滤波后的流量替代真实流量。

**核对方式：**查源码安装端口与实际更新机制；未实现的时间戳、冗余、噪声或故障状态不能算已具备能力。

**示例：**一只温度传感器读数可与热容温度相同，但它的安装节点、公开输出和是否采样仍需明确。

**来源与修订依据：**P01 G24/G25/G119—G121；P02 M17

## M18｜任务、控制与只读展示分工 · 必须
任务产生请求，控制器计算动作，物理系统产生响应，显示只读取信息。任务规划可以在系统内部，顶层不强制机械摆出固定数量的面板或额外任务源。

### 应包含 / 应落实
- 各职责的明确承载类及公开接口。
- 运行显示读取当前量；参数展示引用同一份生效配置。
- 必要的无状态显示换算放在显示行为中。

### 不应这样处理
- 一个未声明的混合读写面板既决定物理状态又统计其完成。
- 为刷新文字新增积分器、重复库存或无用途的周期事件。

**核对方式：**从源码确认读写方向和状态所有权；职责独立不等于必须增加同样的顶层模型数。

**示例：**立方星 CompleteMission 可由环境、航天器和遥测显示组成，任务管理按现有系统内职责保留。

**来源与修订依据：**P01 §07；P02 M18；P04 M18

## M19｜配置权威源与单位统一 · 必须
设计参数、曲线、任务、初态、控制和求解设置各有唯一权威来源。派生总量由清楚的分项关系计算，不能维护两套相互漂移的默认值。

### 应包含 / 应落实
- 稳定参数键、名称、输入单位、内部单位、类别、实际消费者和编辑性。
- 集中单位转换、分项与派生关系。
- 新增可调量进入原配置合同；不可调算法常量单独说明。

### 不应这样处理
- 表中一个值、模型里另一个值；从只读预览或显示缓存再次读取输入。
- 把设计推定称为实机辨识，或为通过验收偷偷降低门槛。

**核对方式：**核对源数据、生成记录和实际使用位置；本版辅助文档/线色修改不得改变任何当前值、公式或单位。

**示例：**电池额定电荷量与能量不是同一个参数；Ah 到 C 的转换在配置链中一次完成。

**来源与修订依据：**P01 G37/G59/G99；P02 M19

## M20｜发布包含可用的离线生成快照 · 必须
外部设计输入在准备阶段生成本地 Modelica 记录、数组和必要资源。交付中包含最后有效快照；求解期不依赖打开 Excel、实时调用 Python 或联网。

### 应包含 / 应落实
- 记录/数组、任务与初态数据；明确加载和离线更新入口。
- 生成文件与输入、代码相符的来源记录。
- 必要资源以实际依赖发布，不要求不存在资源的工程创建目录。

### 不应这样处理
- 只交工作簿和空模型，要求接收者先成功运行生成器才能首次加载。
- 把环境或轨迹的外部实时计算伪称纯 Modelica 总体仿真。

**核对方式：**加载所需文件完整；离线生成失败不覆盖最后有效组。事务细节属 Codex/工具参考，不限定建模师必须采用某种脚本框架。

**示例：**GeneratedScenario 和固化环境记录随工程发布；重新配置是离线操作，不是求解器的一部分。

**来源与修订依据：**P01 G38—G40；P02 M20

## M21｜构型、参考值和限值贯穿一致 · 必须
一次运行的活动构型唯一确定。设计参考、归一化基准、目标请求、实际运行值和允许限值分别命名；改变参考点时同步处理所有相关消费者。

### 应包含 / 应落实
- 构型 ID、配置身份、环境条件及结果作用边界。
- 参考量与曲线坐标、控制和负载的依赖关系。

### 不应这样处理
- 混合不同型号、坐标系、工作边界的数值而不注明。
- 只改额定记录、不改依赖它的归一化表或控制参数。

**核对方式：**从配置键追踪所有使用者；保留旧运行的构型身份，新发布编号不改写旧 RunId。

**示例：**轨道环境、太阳阵安装和表面几何应与本次立方星构型对应；显示面板不拥有另一份构型。

**来源与修订依据：**P01 G116/G117；P02 M21

## M22｜曲线资产、数据节点与算法分离 · 必须
曲线/矩阵作为具有明确轴、单位、来源、版本和用途的资产维护，插值算法与可编辑表值分离。Modelica 数组是当前数据的执行快照。

### 应包含 / 应落实
- 资产 ID、输入轴顺序/单位、输出含义/单位、插值和外推策略、四层工作域、消费者。
- 严格递增坐标、无重复点、完整二维网格、有限值与合法尺寸。
- 一维表两列、二维表明确行轴与列轴；修改来源和影响范围。

### 不应这样处理
- 离线重新按旧公式采样，覆盖用户已修改的表值。
- 把修正因子当绝对量，或把矩阵单元格数当独立设备能力数。

**核对方式：**解析一次权威数值区；只读预览不成为第二源。对于反插值另核对单调支路和支持域。

**示例：**电池开路电压表的横轴是 SOC；执行时查同一张生效表，不在另一个模块保留可覆盖它的默认公式。

**来源与修订依据：**P01 G55/G56；P02 M22

## M23｜参数实际消费与覆盖计数 · 必须
声明已经生效的配置与资产可追溯到实际数学/逻辑用途。写入参数记录、传进 modifier 或出现在面板上，都不等于已经影响模型行为。

### 应包含 / 应落实
- 源 ID→生成键→真实消费者→数学/逻辑位置→适用效应或集成证据。
- 参数、测点、状态、设备、接口各自固定计数范围。
- 已实现、未激活、待证、失败、范围外和退役的独立状态。

### 不应这样处理
- 增加别名、目录和重复参数提高覆盖率；把覆盖率等同实机精度。
- 一次多参数变化为所有单参数自动判定通过，或声称全部可唯一反演。

**核对方式：**按用途选局部解析、短激活和必要整体证据；不要求每个参数反复运行全任务。

**示例：**热容值必须进入热量与温度变化关系；只在 Documentation 表里列出热容不能算已消费。

**来源与修订依据：**P01 G57/G58/G103—G106；P02 M23

## M24｜数值保护与物理可用域分开 · 必须
分别说明原始数据域、工程延拓域、已运行轨迹域和经验证物理域。数值正则化、钳位、noEvent 和 smooth 不自动构成安全限制或真实能力。

### 应包含 / 应落实
- 保护表达式的原因、作用量、范围与误差影响。
- 超界诊断保留未裁剪的原始查询量。
- 真实顺控保留必要事件；迭代试探点与接受解分别讨论。

### 不应这样处理
- 所有 if 一律加 noEvent，所有曲线一律标 smooth(1)。
- 只为消除超界状态扩大曲线而无工程依据；接受解越界却只检查钳位值。

**核对方式：**检查边界附近时窗与原始域裕量，数值可解和用途有效分别给结论。

**示例：**插值矩形内运行只证明数值支持域；不能据此宣布电池、姿态执行或热过程已经实物验证。

**来源与修订依据：**P01 G53/G54/G114/G115；P02 M24

## M25｜结果有单一语义合同 · 必须
结果合同登记语义 ID、变量路径、说明、单位、身份、时序、必要分辨率与用途。工具适配只解决命名、保存选项和文件格式，不改变物理行为。

### 应包含 / 应落实
- 必需输出清单与原始变量的映射；新增行为所需的少量诊断。
- 保存、加载、显示和导出分别核对；允许合乎用途的输出筛选。
- 声明注释作为描述来源，不靠新增输出别名实现注释。

### 不应这样处理
- 为了文件小裁掉真实峰值、慢工况或必要内部量。
- 用静态参数表、单个终点或零线截图代替完整轨迹。

**核对方式：**核对原始数据中的变量、时间和单位；别名合并后的描述显示受工具行为影响，不能只靠 Documentation 保证。

**示例：**保留遥测中命令、实际状态和温度的不同路径；注释更新后重新翻译运行才能生成新的结果描述元数据。

**来源与修订依据：**P01 G45/G80—G82/G126；P02 M25

## M26｜运行证据可读且来源真实 · 必须
只有实际取得的证据才能声明相应工作完成。加载、编译、初始化、积分结束、结果存在、结果可读和工具显示是不同状态。

### 应包含 / 应落实
- 运行身份、实际源码/配置、引擎/库版本、时间范围、原始文件和处理方法。
- 完整、有限且合乎预期的必需量；事件相同时间点可以保留。
- 每个平台自己的执行和显示状态。

### 不应这样处理
- 未运行却写“已通过 MWorks”；读取旧结果后声称重新编译仿真。
- 超时结果补尾或分段拼接成一次完整任务；挑最好耗时冒作全部运行。

**核对方式：**未知、截尾、未检查独立标记。模型层面用户认可不等于本次补丁已经复跑。

**示例：**辅助补丁可以具有源码不变量证据，但本次未启动求解器时，新的编译与仿真状态仍写 NOT_RUN。

**来源与修订依据：**P01 G61/G82/G124—G130；P02 M26

## M27｜项目验收与独立守恒核查 · 必须
任务、场景、门槛、时窗和必需检查由项目自身定义。若声明质量、能量或库存核查通过，应能由真实原始分项独立复算。

### 应包含 / 应落实
- 系统边界、库存、输入输出、内部交换及适用全过程限制。
- 必要转换、平台窗口、峰值、持续时间与数值对照。
- 空窗口、缺列、未达终点的明确失败或待查状态。

### 不应这样处理
- 读取模型内人为恒零残差作为独立证明；内部交换重复计入边界。
- 跳过失败场景，或用稳态均值替代全过程限制。

**核对方式：**按预先声明的 RequiredChecks 逐项汇总；结果图的数量不是通用验收门槛。

**示例：**数据库存用入流、出流和丢弃流核账；只有存储容量参数不等于数据传输和任务完成已经验证。

**来源与修订依据：**P01 G60/G107/G111；P02 M27

## M28｜结论分层与建议不越级 · 必须
架构符合性、项目验收、数值运行、物理域、外部保真与安全结论分别报告。适用必须项逐项成立；未知或缺项不自动变成通过。

### 应包含 / 应落实
- R 必须、S 建议、F 参考及项目附加要求的独立清单。
- PASS/FAIL/UNKNOWN/NOT_CHECKED/NOT_APPLICABLE 的适用语义。
- 校准数据、留出验证和外推边界。

### 不应这样处理
- 用整体平均分掩盖必须项失败；把文档、图标参考变成隐含物理重构任务。
- 把“模型能跑”直接换算为实机准确度或安全完整性。

**核对方式：**逐键判定且检查集非空；适用性不明保持未知。已有工程采用情况与新增代码的核查状态分别记录。

**示例：**图标已人工认可可沿用，不要求满足每个参考尺寸；声明实际连通的端口仍必须确实连通。

**来源与修订依据：**P01 G52/G130—G133；P02 M28；P04 分级

## M29｜按用途管理规模与性能 · 建议
建议项目分别设定任务时间、精度、方程规模、墙钟和结果体积的预算，区分硬上限与优选目标。MOSAIC 不规定所有模型统一的秒数、MB、状态数或图数。

### 应包含 / 应落实
- 真实引擎、硬件、阶段计时与可得的状态/事件/求解统计。
- 低代价短诊断、事件和非线性定位、输出策略的对照。

### 不应这样处理
- 把源码行数当方程数；假设少状态必然快。
- 通过放宽精度、减少任务或隐藏峰值宣称优化。

**核对方式：**同源、同硬件、同口径比较；具体超时监督是项目执行要求，见附录 C。

**示例：**对电热快速变化与轨道长任务分别选择观测分辨率，不能仅用低频长期存盘证明所有峰值。

**来源与修订依据：**P01 G41/G44/G122；P02 M29

## M30｜局部替换保持边界与旧用途 · 建议
建议以明确接口替换部件、逐步细化本构，保持已有用途所需的输入输出、状态归属和配置链；改变接口时显式迁移消费者。

### 应包含 / 应落实
- 替换前后假设、单位、方向、时序、有效域和初始化的对照。
- 受影响的配置、连接、结果和证据清单。

### 不应这样处理
- 接口同名就宣称等效；无解或空轨迹也当作保持保证。
- 一个部件升级带来无授权的全项目重构或目录迁移。

**核对方式：**保证声明仍按 M28 的必须真实性要求。新部件含装配时重新登记父层角色，不靠前缀隐藏变化。

**示例：**细化电池内阻模型时保留电端、热端和 SOC 语义；需要增加新状态时属于行为升级，不是说明文档补丁。

**来源与修订依据：**P01 G50/G51/G91；P02 M30；P04 M30

## M31｜发布身份与辅助修改保护 · 必须
一个活动发布有唯一源码根、确定入口、依赖、配置及明确适用的证据。规范版本、项目发布号、配置/协议版本和 RunId 分开维护。

### 应包含 / 应落实
- 仅辅助修改的具体白名单；输入数据、运行方程和未授权注解保护。
- 根包 version 唯一且与发布一致；uses(Modelica(version=...)) 不被改成项目版本。
- 当前文件字节清单与历史运行来源分别保存。

### 不应这样处理
- 去掉全部 annotation 后声称行为不变，忽略 experiment、Evaluate、Inline、资源路径等。
- 全文件替换 version；新发布号覆盖旧运行记录或协议常量。

**核对方式：**文档/名称补丁只豁免 Documentation 和指定 string-comment。仅线色补丁另豁免实际 connect 的 Line.color，保留 points、厚度、Icon/Diagram 图案及全部其他 token。

**示例：**发布号可从一个补丁号递增到下一个；内部任务配置身份若未改变就保留原值，不能为美化编号改变运行常量。

**来源与修订依据：**P01 G65/G66/G136；P02 M31；P05 辅助边界

## M32｜面向使用的 Documentation 与字段注释 · 建议
建议逐类说明真正帮助建模师使用模型的信息：用途、调用位置、接口、关键配置、内部组成或行为、状态初态和具体限制。按类的实际内容取舍，不填模板废话。

### 应包含 / 应落实
- package 说明入口和包内职责；TB 说明任务与配置；SB/AB 说明组成和边界。
- BU/LU 说明本构或基类、参数、初态和实际限制；connector/record/function 说明成员或调用合同。
- 结果变量、参数、接口字段使用准确的声明 string-comment；必要时保留统一说明表。

### 不应这样处理
- 逐类重复“连接与责任”统计段、“仿真后如何查看”教程或“Documentation 辅助更新……”免责声明。
- 删除实际的使用边界、许可和初态说明；为显示注释增加变量、改变 unit/displayUnit/HideResult 或输出过滤。

**核对方式：**目录和类说明与当前源码一致；运行方法和发布记录集中在根说明。逐类 Documentation 是建议，但已写内容的真实性受 M28 约束。

**示例：**声明 Real temperature(unit="K") "设备温度"；Documentation 解释它对应的热节点，不在每个类重复结果窗口的操作教程。

**来源与修订依据：**P02 M32；P04 文档附录；P05 删改要求

## M33｜图标、布局与接口连线色 · 建议
建议用原生 Icon 解释对象功能、用 Diagram 解释真实组成，沿用已认可图案。装饰配色不覆盖接口语义；接口线色按类型来源处理，不能给所有线套品牌蓝或领域微色。

### 应包含 / 应落实
- MSL 原生与派生接口：恢复/保留相应 MSL 默认连接色。
- 真正自定义 connector 的整体连线：匹配其主色；复合接口的 MSL 类型成员线按该成员原生色处理。
- 默认黑色主轮廓与小面积领域微色、双尺度可辨、必要文字；具体图案见附录 A。

### 不应这样处理
- 把派生 Frame/HeatPort 当新接口随意改线色；用父系统颜色涂所有子线。
- 删 color 属性后就断言自动恢复 MSL 色；Line 默认黑色不等于各族连接色。
- 借图形维护改动 connect、类型、配置或状态；重画已认可 LOGO。

**核对方式：**沿实际端点类型、别名与继承链核对。自定义整体与 MSL 字段分别登记；未知来源先保留待查，不猜颜色。此条本身建议级，本次项目明确选择线色规则作为辅助交付要求。

**示例：**派生 MechanicalPort 即使 Icon 使用紫色，其 Frame 连线仍取 MSL 灰色；自定义多路电源整体可用橙色，内部 Pin 连线仍蓝色。

**来源与修订依据：**P02 M33；P03 附录 A/B；P05 线色要求；T01/T02

## M34｜目录、资源与工程简洁性 · 建议
建议保持一个清楚且稳定的活动根，包按职责组织。语言包层次与文件夹结构一致，避免重复嵌套同名项目或遗留多个“当前”工程。

### 应包含 / 应落实
- 根 package.mo、必要 package.order、Modelica 源码和实际依赖资产。
- 离线生成、检查和发布辅助集中到既有 Scripts 或等价位置。
- 压缩包版本与内部语言根目录分别管理。

### 不应这样处理
- 为符合模板强建 Config/Tests/Documentation 等空包，或无条件删除有资源引用的 Resources。
- 因图标或注释更新迁移全部路径；把必要历史证据伪装为活动源。

**核对方式：**从入口和资源引用检查包能否完整定位。规范不统一规定目录层数，明确项目自己的额外交付结构。

**示例：**OneSatSim 为语言根目录，ZIP 名称可以携带发布版本；包内引用不跟随压缩包名称变化。

**来源与修订依据：**P01 G46/G65；P02 M34

## M35｜以当前用途推动耐用性与细化 · 建议
建议先解决影响使用的边界不清、配置漂移、状态重复和结果不可解释问题，再增加物理颗粒度。可理解、可配置、可替换与可复核是耐用性的具体抓手。

### 应包含 / 应落实
- 对结构、稳态、瞬态、测量和极限域分别列差距。
- 以局部可定位的候选和回退点完成有限迭代。

### 不应这样处理
- 用文件数量、图标数量或参数数量包装保真度提升。
- 未有数据支撑承诺“遵守规范就一定达到实机精度或永不失效”。

**核对方式：**明确收益、成本、影响范围和实际证据；未达到的用途继续披露，不阻断合理工程开发。

**示例：**增加电池热耦合前先保证原电端、参数源和结果描述清楚；更精细不是更多无用包装。

**来源与修订依据：**P01 G62/G131/G135；P02 M35

## M36｜按任务选用扩展分析 · 参考
故障、安全、不确定性、形式化镜像、外部集成和专门验证设施均按任务需要选用，不是每个总体模型的通用组成。

### 应包含 / 应落实
- 扩展资产通过同一名义模型与公开边界接入。
- 新增能力的用途、依赖、参数、观察判据与证据。

### 不应这样处理
- 为形式完整创建独立故障库、测试树或第二套系统；把名义仿真通过等同安全认证。

**核对方式：**参考扩展仅在用户授权后实施；扩展的事实性结论仍服从主规范。

**示例：**研究供电故障时再加入故障资产和观察判据；文档与配色补丁不自动创建故障通道。

**来源与修订依据：**P01 G31/G133；P02 M36；P04 M36
