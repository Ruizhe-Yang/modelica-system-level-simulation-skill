# 附录 A｜Modelica 图标与 Diagram 绘制参考

**参考属性。** I-01—I-20 是图形实施参考，不是新的主规范条款。M33 的审美选择保持建议级；图形修改不能破坏 M04 的真实连接、M10 的接口语义和 M31 的辅助边界。若项目明确要求“MSL 原生线色”，它是本次视觉交付的指定要求，不变成物理方程重构许可。

## A.1 图案如何表达模型功能

| 编号 | 参考做法 | 实际落点 |
|---|---|---|
| I-01 | 先明确工程身份、典型结构、输入输出和与同族的关键差别 | 每个图案提取两三项最有辨识度的特征，不从文件名机械套模板 |
| I-02 | 外框—领域提示—功能主体—真实接口—简短标题五层构图 | 外框和角标可省略；功能主体与真实端口优先，文字不重复 |
| I-03 | 统一线条、留白与尺度，不统一成相同图案 | 电池、反作用轮、相机、算法单元应有本质不同的主体 |
| I-04 | 参考坐标 −100…100；接口附近留通道 | 尺寸是起点不是强制值；面板可以原生设计为矩形 |
| I-05 | 黑色工程主轮廓、小面积领域微色 | **仅图案的艺术用色**，不得据此重涂 MSL 连接线 |
| I-06 | 同时检查父层缩略图和独立 Icon | 缩小时看身份，放大后见机构；不依赖微小文字区分类别 |
| I-07 | 同族有共同轮廓，也保留关键区别 | 电池与电源调理不都画成闪电；飞轮与磁力矩器不都画成圆盘 |
| I-08 | 算法按作用画，不伪装硬件 | 插值画表/曲线，仲裁画分支，转换画输入输出关系 |

### 领域图案参考：不规定模型必须具备这些设备

| 对象 | 适合强调的图案 | 应避免的误导 |
|---|---|---|
| 航天器总体 | 体框、安装面、项目已有太阳阵或天线形态 | 图案画出当前模型没有的展开机构，暗示已实现该能力 |
| 太阳阵 | 电池网格、光照与电能转换 | 用同一个电池包图案代替发电器件 |
| 电池与电源调理 | 电芯正负极；调理器突出变换/稳压关系 | 混淆储能与电能转换 |
| 反作用轮与磁力矩器 | 转子角动量；线圈磁芯与磁矩方向 | 只用“旋转”表示两种完全不同的作用 |
| 相机与星敏感器 | 镜头光轴与成像；星点及姿态测量 | 只画通用电子方盒，不区分观测对象 |
| 数据记录器与通信 | 存储介质与读写；天线/链路与上下行 | 把数据库存和通信带宽画成同一个仪表盘 |
| 热容、加热器、散热器 | 温度节点；加热线；传热路径/翼片 | 所有热模型一律温度计，无法判断储热和传热 |
| 控制/状态逻辑 | 芯片、反馈、状态分支 | 画出不存在的机械执行机构 |
| 环境、任务、显示 | 外界场；轨迹/时序；只读曲线或数值 | 图案暗示它们各有一份物理系统 |

## A.2 接口、文字与父层可读性

| 编号 | 参考做法 | 实际落点 |
|---|---|---|
| I-09 | 先按真实类型区分信号、电气、热、机械、流体和复合接口 | 物理无因果口不因箭头画法变成单向输入；颜色不是类型依据 |
| I-10 | MSL 原生接口优先保留原图，自定义图案不遮挡连接位置 | 派生类是否仍为 MSL 接口从 extends/别名链判定 |
| I-11 | 小图少字，完整成员说明放 Diagram 或 Documentation | 可以不画接口文字；标识符不因中文显示改名 |
| I-12 | 标题、实例名、接口说明分区，避免同位重复 | `%name` 是实例名；类说明不是标题图元，也不是完整浏览器标签 |
| I-13 | 先统一 Text 范围和目标缩放，再选择字号与可用字体 | `fontSize=0` 自动适配不保证不同框内像素一样大；不分发字体文件 |
| I-14 | 接口密集时分组和分层，而不是无限缩字 | 保留主要关系，详细类型/单位交给放大页面或端口说明 |
| I-15 | Icon 表示身份，Diagram 表示组成和真实交互 | 不将完整目录、版本统计和长说明塞入小 Icon |
| I-16 | 移动组件后同时核对父层连接端点 | 修改 Placement 应联动 Line.points，不能改实际 connect 端点“接上图” |
| I-17 | 清理低价值脚注，不清理真实说明 | 不重复“输入 X 项/详情见文档”等缩小不可读文字 |

MOSAIC 文档使用品牌蓝，**Modelica 工程图不要求全部变蓝**。新项目可约定图形短英文＋中文说明；已有项目保留经过人工认可的语言组合。用户没有请求时，不在此次线色更新中修改字体、Icon 标题或端口形状。

## A.3 Diagram 的逻辑布局

优先沿主要能量、物质或信息路径安排位置，给关键系统更醒目的面积；控制反馈放在能看出闭环的一侧，环境和任务边界放在入口附近，显示位于输出区域。布局不要求机械矩形网格，也不要求人为打乱已经清楚的对齐。应检查画面逻辑，而不是只追求几何整齐。

实例与端口移动、旋转、镜像和缩放后，其父层端点应由实际变换组合确定。连接可采用短直线或正交折线，必要交叉不表示连通。多条共线连接可以共用通道，但不能因此漏掉实际 connect；图形坐标更改不是结构安装参数更改。

## A.4 I-18：图形语法和标准字段

| 图元/注解 | 常用属性 | 常见问题 |
|---|---|---|
| Rectangle | extent、radius、lineColor、lineThickness、fillPattern | 使用非标准 RoundedRectangle；把 Line.thickness 误用到形状 |
| Line | points、color、thickness、pattern、arrow | 图案线和 connect 的线混为一谈；宽度/端点无授权一起改变 |
| Polygon | points、lineColor、fillColor、fillPattern | 点序自交；小尺寸只剩无法辨识的色块 |
| Ellipse | extent、startAngle、endAngle、closure | 圆弧闭合/填充掩盖其他图元 |
| Text | extent、textString、fontSize、textColor | 重复标题、框太窄、依赖目标软件不存在的字体 |
| Icon / Diagram | coordinateSystem、graphics | 同一类重复添加同名 Icon 分量；删除图元后遗留尾逗号 |
| Placement | transformation、iconTransformation | 接口与组件变换不同，复制坐标却未检查父层 |
| Documentation | info、revisions 等实际已有内容 | HTML 转义出错；覆盖原许可或真实使用限制 |

上述图元字段以 Modelica 3.6 图形定义为语言核对基线。旧工具的显示兼容写法可以在项目内保留，但不得未经测试宣称某个私有属性跨工具通用。对现有工程，优先做最小修改；括号配平不等于完成 Modelica 语法或 GUI 渲染验证。〔T01〕

```modelica
annotation(Icon(
  coordinateSystem(extent={{-100,-100},{100,100}}, preserveAspectRatio=true),
  graphics={
    Rectangle(extent={{-88,-88},{88,88}}, radius=4,
      lineColor={0,0,0}, fillColor={255,255,255},
      fillPattern=FillPattern.Solid, lineThickness=0.5),
    Rectangle(extent={{-48,-30},{48,38}},
      lineColor={0,0,0}, fillColor={235,242,248},
      fillPattern=FillPattern.Solid),
    Line(points={{-26,4},{-6,4}}, color={0,0,0}, thickness=0.8),
    Line(points={{-16,-6},{-16,14}}, color={0,0,0}, thickness=0.8),
    Line(points={{14,4},{34,4}}, color={0,0,0}, thickness=0.8),
    Text(extent={{-76,-80},{76,-56}}, textString="Battery",
      fontSize=0, textColor={0,0,0})
  }));
```

此代码只演示 Icon；它没有电池端口和物理行为。真实 connector 应由模型声明并按自身图形渲染，不能拿两条装饰线代替端子。

## A.5 I-19：图形维护检查顺序

盘点已认可图标与真实端口 → 提取功能区别 → 选择局部模板 → 安全替换所需注解 → 检查独立 Icon 与所有受影响父层 → 对照源码差异 → 按实际可用工具登记语法与渲染状态。若本次只允许线色修改，范围止于实际 connect 的 Line.color，不执行模板重画或重排。

检查记录分为：真实拓扑、图形存在性、端点可辨、文字/缩放、语言语法、目标工具显示。源码预览不是 MWorks 截图；没有打开目标软件就保留 NOT_CHECKED。参考画法没有采用，不等于主规范必须项失败。

## A.6 I-20：连线颜色继承规则（v0.8 新增）

**先解析端口，再选择颜色。** 读取 connect 两端的实际声明；若端口经本地别名或多级 extends 仍来源于 MSL，则采用其原生族的连接色。对于真正自定义的复合接口，应区分“整体连接”和“成员连接”：整体跟随接口的主色，MSL 类型成员仍跟随成员类型。

| MSL 4.0.0 常用族 | 原生连接色基线 RGB | 需要避免 |
|---|---|---|
| RealInput / RealOutput | 0, 0, 127 | 跟随载荷/热/控制等所在系统的领域色 |
| BooleanInput / BooleanOutput | 255, 0, 255 | 与 Real 同涂蓝色或与自定义总线同涂青色 |
| IntegerInput / IntegerOutput | 255, 127, 0 | 以字段内容是状态码为由任意重画 |
| Electrical.Analog Pin | 0, 0, 255 | 自定义电源大端口的橙色覆盖内部 Pin |
| Thermal.HeatTransfer HeatPort | 191, 0, 0 | 使用 Icon 的微色代替原生热连接色 |
| Mechanics.Rotational Flange | 0, 0, 0 | 将灰色填充误认为线色 |
| Mechanics.Translational Flange | 0, 127, 0 | 将三维 Frame 与一维平动混为同族 |
| Mechanics.MultiBody Frame | 95, 95, 95 | 因本地派生 Frame 画成紫色就把连接改紫 |
| Fluid.FluidPort | 0, 127, 255 | 从工作介质名猜颜色，或忽略 stream 语义 |

这是一份**固定于 MSL 4.0.0 的常用基线**，不是所有 Modelica 版本/全部接口的万能色表。其他连接器、不同版本或同族特殊类型须核对实际库源文件与工具规则；未知项不能静默套色。色表取自 MSL 原生图形/使用约定，工具需要显式 `Line(color=...)` 时写回同一原生值即可。〔T02〕

**不要把删除 color 当作恢复原色。** Modelica 图形 Line 的默认颜色是黑色，不会仅凭省略该属性就保证所有工具重新推断热口红色或信号蓝色。因此本版对已被改色的实际连接显式恢复相应 MSL 值，而不是全量删除属性。〔T01〕

```modelica
// 即使 MyHeatPort 只是 HeatPort_a 的本地派生，仍使用原生热连接色。
connect(component.heat, thermal.port)
  annotation(Line(points={{0,0},{40,0}}, color={191,0,0}));

// 自定义复合总线的整体可以使用它自己的主色。
connect(source.telemetry, sink.telemetry)
  annotation(Line(points={{0,20},{40,20}}, color={0,100,100}));

// 同一复合总线中的 value 若声明为 MSL RealInput，成员线仍是 MSL Real 色。
connect(sensor.y, sink.telemetry.value)
  annotation(Line(points={{0,40},{40,40}}, color={0,0,127}));
```

批量处理建议保留：类路径、源 connect、两端实际类型、继承依据、旧色、新色、是否自定义整体及未解析原因。**只豁免实际 connect 的 color，不豁免 Icon 中所有 Line，也不豁免 Line.points。** 当前 skill 的静态解析工具覆盖已登记的常用 MSL 成员；遇到未知类或动态色表达式停止自动写回并要求复核。
